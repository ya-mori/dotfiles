# チーム・連絡先

チームメンバーと Slack チャンネルの一覧。
**実データは同じディレクトリの `docs/team/private.md` にある**（実名・チャンネル名を含むため）。
このファイルは列の意味と使い方だけを持つ。

---

## 使いどころ

| 場面 | 見る列 |
|---|---|
| 対外メッセージの宛先を判断する | メンバーの **距離感**。`他チーム` / `社外` なら内部用語を避ける（`ore-message` 参照） |
| 「誰に聞くか」を判断する | メンバーの **担当領域**。候補が複数なら決め打ちせず確認する |
| 投稿先チャンネルを選ぶ | チャンネルの **用途** と **参加範囲**。`社外含む` なら内部用語を避ける |
| レビューを依頼する / PR の作者を特定する | メンバーの **GitHub**。Slack ID と同一人物として紐づける |

---

## 列の定義

### メンバー

| 列 | 内容 |
|---|---|
| 名前 | 会話で使う呼称 |
| 担当領域 | 何を聞ける人か |
| 距離感 | `同チーム` / `他チーム` / `社外`。**語彙と丁寧さはこれで決まる** |
| Slack | メンション用の ID |
| GitHub | GitHub ユーザー名。PR・レビューでの同一人物判定に使う |

### Slack チャンネル

| 列 | 内容 |
|---|---|
| チャンネル | `#` 付きの名前 |
| 用途 | 何を投稿する場か |
| 参加範囲 | `同チーム` / `部署横断` / `社外含む` |
| 作法 | スレッド運用・メンションの習慣など、外すと失礼になる暗黙のルール |

---

### そのほか private 側が持つもの

| セクション | 内容 |
|---|---|
| ユーザーグループ | Slack のユーザーグループ（`<!subteam^...>`）と、その使い分け。全体周知用か特定領域用か |
| 未確認事項 | 埋められなかった列と、その理由。次に埋めるときの手がかりとして残す |

---

## 表に無い人・チャンネルを見つけたら

**その場で `docs/team/private.md` に追記する。** 気づいたときに書かないと二度と書かれない。

追記するタイミング（実際に接触したとき）:

- Slack のチャンネルやスレッドを読んだ
- 対外メッセージのドラフトを作った
- PR のレビューを依頼した / レビューを受けた
- コミットや PR の作者として知らない GitHub ユーザー名が出てきた

追記のルール:

- **埋められない列は空欄のままでよい。** 分かった時点で埋める
- **推測で埋めない。** 特に `距離感` `参加範囲` `作法` は外すと失礼になるため、確信が持てなければ空欄にしてユーザーに確認する
- 同一人物が Slack と GitHub で別名の場合、同じ行にまとめる（別人として二重登録しない）
- **追記したら作業報告の最後に一言添える。** 黙って増やさない

---

## 運用

- **用途に紐づかない列は作らない。** どの場面で参照されるかを「使いどころ」に書けない列は、結局埋められず書かれなくなる
- 列を増やすときは「使いどころ」にも1行足す
- private 側が無い環境では、このファイルだけで「そういう情報がある」と分かればよい
