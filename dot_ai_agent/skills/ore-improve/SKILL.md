# ore-improve — 学びを恒久ルールへ昇格させる

セッションで得た学びは memory に溜まる。**溜めるだけでは行動は変わらない。**
このスキルは、溜まったものを恒久ルールへ昇格させる工程だけを担う。

## このスキルがしないこと

**収集しない。** 収集は memory 機構（Claude はネイティブ、Codex は `core.md`
「Learning Capture Guidelines」）が既にやっている。

旧 Self-Improvement Loop は `PostToolUse` hook でツール実行を収集していたが、
**集めていたのが「何のツールを叩いたか」の羅列で、読んでも次の行動が変わらなかった**。
加えて hook が 2026-07-08 にサイレント停止し、36日間気づかれなかった。
**同じものを作り直さない。**

---

## 前提（起動時に即実行・スキップ禁止）

1. **昇格先の判定基準は dotfiles の README「共通ルールへの昇格を判断する」が本体。**
   `chezmoi source-path ~/.ai_agent/instructions/core.md` でソースの場所を解決し、
   同リポジトリの `README.md` を読む。このファイルに判定基準を複製しない
2. **書き換えは chezmoi のソース側。** ターゲット（`~/.ai_agent/` `~/.claude/` `~/.codex/`）を
   直接編集すると次の `chezmoi apply` で消える
3. **このリポジトリは public。** 昇格させる文面に識別子・社内固有名詞・実名を持ち込まない。
   秘匿部分は `docs/{topic}/private.md` へ切り出す

## 入力源

| 源 | パス | 誰が書くか |
|---|---|---|
| Claude ネイティブ memory | `~/.claude/projects/*/memory/*.md` | Claude Code が自動で書く |
| 共有 inbox | `~/.ai_workspace/memory/*.md` | Codex（`core.md`「Learning Capture Guidelines」に従う） |

- **`MEMORY.md` は索引なので対象外。**
- Codex の `~/.codex/memories_1.sqlite` は**入力に使わない** —— 2026-08-31 時点で0件、
  かつ SQLite の内部テーブルで markdown としての読み書き口が無い。稼働し始めたらここに足す

## 回す順序

| # | ステップ | 書き込み | 人を待たせるか |
|---|---|---|---|
| 1 | 集める | なし | いいえ |
| 2 | 昇格先を判定する | なし | いいえ |
| 3 | **変更案の提示 → `y/n` → 書き込み** | あり | **ここだけ** |

### 関門は1つだけ

**ステップ1〜2は読み取りのみで最後まで走り切る。途中で承認を求めない。**
読み取りに承認は要らない（`core.md`「読み取り専用の操作は承認不要」）。

### 途中経過は「報告」であって「確認」ではない

ステップ1〜2で人に見せるのは**1〜2行の進捗だけ**。表を出さない。

```
memory 72件のうち未昇格は 14件。うち feedback 型 9件を昇格候補として判定します。
```

---

## ステップ1: 集める

1. 両方の入力源から `.md` を集める（`MEMORY.md` は除く）
2. **frontmatter に `promoted:` があるものを除外する**（昇格済み）
3. `type` で優先度を付ける

| type | 扱い |
|---|---|
| `feedback` | **最優先。** 行動を変えるために書かれたもの |
| `user` | 拾う。ツールをまたいで効く |
| `project` | **原則対象外。** そのプロジェクトでしか効かない |
| `reference` | **対象外。** 外部資源へのポインタ |

**同じ趣旨が2つ以上のプロジェクトに出ていたら、それは昇格の強い根拠。**
1箇所で言われたことは好みかもしれないが、複数箇所で言われたことは共通ルールの取りこぼし。

---

## ステップ2: 昇格先を判定する

README の判断フローに沿って振り分ける。

| 昇格先 | ソース | 何を置くか |
|---|---|---|
| `core.md` | `dot_ai_agent/instructions/core.md` | 両ツールに同じ振る舞いをしてほしいルール |
| `CLAUDE.md` | `dot_claude/CLAUDE.md.tmpl` | Claude 固有機能（hook / サブエージェント / プラグイン）に依存するもの |
| `AGENTS.md` | `dot_codex/AGENTS.md.tmpl` | Codex 固有機能に依存するもの |
| skill | `dot_ai_agent/skills/<name>/SKILL.md` | 特定の作業手順の中でしか効かないもの |
| docs | `dot_ai_agent/docs/<topic>/public.md` | 運用ルールの本体。識別子は `private.md` へ |

### 昇格させない判断も同じくらい重要

| 状況 | 判断 |
|---|---|
| 1プロジェクトにしか効かない | memory に留める |
| 既に同趣旨のルールがある | **昇格ではなく既存の記述を直す。**新しい行を足さない |
| 一度きりの事情 | memory に留める |
| ルールにすると例外だらけになる | 留める |

**ルールを足すときは、代わりに削れるものが無いか見る。**
`docs/task-system/public.md`「育て方」と同じ —— 足すだけだと誰も読まなくなる。

---

## ステップ3: 変更案の提示（唯一の関門）

**「昇格する」「見送る」の2区分だけ**を表で出す。

### A. 昇格する（N 件）

| 学び | 出所 | 昇格先 | 追記 / 改訂 |
|---|---|---|---|
| 判断が必要なものを「判断が必要 / 不要 / 変更なし」で分けて出す | chezmoi, claude-workspace（2箇所） | `core.md` | 追記 |
| 不可逆な選択は括弧書きにせず番号で並べる | chezmoi | `core.md` | 既存「Conversation Guidelines」を改訂 |

**出所が複数なら全部並べる**（それ自体が昇格の根拠になる）。

### B. 見送る（N 件）

1行ずつ理由を書く。**「見送り」を件数だけにしない** —— 次回また同じものが候補に上がる。

`y/n` を1回だけ取る。

---

## 書き込み（ステップ3の承認後）

1. chezmoi のソースを編集する
2. `chezmoi apply` でターゲットへ反映する
3. **昇格元の memory の frontmatter に印を足す**

   ```yaml
   ---
   name: separate-decisions-from-noise
   promoted: 2026-08-31 core.md
   ---
   ```

   - **ファイルは消さない。** なぜ昇格させたかの経緯が残り、次回の抽出から自動で外れる
   - memory は chezmoi 管理外なので、ターゲットを直接編集してよい
4. `chezmoi diff` が空であることを確認する
5. `git status --short` に `private` が出ていないことを確認する

---

## 完了報告

- 昇格 N 件 / 見送り N 件
- 昇格先の内訳（`core.md` N 件 / `CLAUDE.md` N 件 / …）
- **削った既存ルールがあれば** その理由
- **`core.md` へ昇格させたものは、なぜ共通と判断したかを一言添える**（README の判断フローの要求）

---

## この仕組みが壊れたらどう分かるか

**hook も常駐プロセスも持たない。** 起きうる失敗は「起動していない」だけで、
黙って動かなくなる部品が無い。

起動の導線は `ore-task` の完了報告（未昇格件数を必ず出す）。
**人が居るときにしか走らないが、その代わり壊れない。**
旧方式は自動で回る代わりに、止まったことが36日間分からなかった。

**困ったことが出てから足す。想像で足さない。足すときは代わりに削れるものを探す。**
