# Slides（資料作成・推敲）スキル

資料は「内容の確定 → アウトライン → 骨組み → 文言 → 構成レビュー → 検証」の順で作る。
後工程ほど手戻りが高くつくため、前の工程が固まる前に次へ進まない。
推敲だけを頼まれた場合も、まず該当フェーズを特定してそこから入る。

---

## フェーズ構成

| フェーズ | やること | 完了条件 |
|---|---|---|
| 0. 内容確定 | 伝えたいことの核を言語化する | 核が1〜2文で言える |
| 1. アウトライン | 構成フレームに沿ってテキストで確定 | ユーザーが「これでいく」と言う |
| 2. 骨組み生成 | ツールにアウトラインだけを渡す | 全ページが存在する |
| 3. 文言パス | ページ単位で文言を適用・調整 | 全ページ反映＋見た目確認済み |
| 4. 構成レビュー | 下記チェックリストで通し確認 | 指摘ゼロ or ユーザー判断で確定 |
| 5. 検証 | 原寸で書き出して目視 | 崩れゼロ |

---

## Phase 0: 内容確定

- 資料作りの中で考えを固めようとしない。**伝えたいことが未言語化なら先に `ore-think` で壁打ちし、合意済みアウトラインを作ってから戻ってくる**
- 確認すること: 誰に見せるか／その場で何が決まれば成功か／これは決定の通知か・提案（たたき台）か
- 表に出さない意図（裏の狙い）があれば聞き出し、資料に書かないリストとして控えておく

## Phase 1: アウトライン設計

- 構成フレームを1つ決める（例: WHY → HOW → WHAT、現状 → 課題 → 提案 → 次アクション）
- **1スライド1メッセージ**。各スライドの役割を1文で書けること
- 理想の流れは「各スライドが、前のスライドで聞き手に生まれる疑問に答える」連鎖になっていること
  （例:「自分で決める」→ *どこまで自由？* →「守るのは3つだけ」→ *チームはどう保つ？* →「週1回の会」）
- 文言は聞き手の日常語で書く。社内で通じない抽象語・カタカナ語は言い換える
- アウトラインはテキストファイルで確定し、以後これを「正」とする

## Phase 2: 骨組み生成

- 生成ツール（AI 生成・テンプレート等）には**アウトラインだけを渡す**。デザイン指定・配色・フォントを混ぜない（構成の質とデザインの質は別々に上げる）
- 生成物はページ構成のたたき台とみなし、文言はこの後の文言パスで「正」に置き換える

## Phase 3: 文言パス

- **1ページずつ**適用し、そのページの見た目を確認してから次へ進む（まとめて直してまとめて確認、をしない）
- 折り返し・あふれの対処は優先順で: **①文言を短縮 → ②文の区切りに明示改行 → ③フォント縮小**
- 単語の途中で行が折れていたら必ず直す（「プロダ/クト」「オー/プンに」は不可）
- 見出し・バッジ類は枠に1行で収まる字数に切り詰める（本文に意味を持たせ、見出しはラベルに徹する）

## Phase 4: 構成レビュー（チェックリスト）

文言が入った状態で通し読みし、以下を確認する。

1. **役割の1文テスト** — 各スライドの存在理由を1文で言えるか。言えない・他ページと同じになる → 統合か削除
2. **限定・強調は1回だけ** — 「〜だけ」「たった◯つ」のような限定の主張はデッキ全体で1回に絞る。複数あると全部の切れ味が死に、「結局いくつあるの？」になる
3. **前方参照の禁止** — 用語・固有名詞は初出のページで説明されているか。**ページを入れ替えたら毎回チェックする**（入れ替えで最も起きやすい事故）
4. **消した情報の行き先確認** — スライドから情報を削るときは、他ページでカバーされているか具体的に確認してから消す。消えたことをユーザーに報告する
5. **語弊チェック** — 聞き手が拡大解釈しそうな言い切りに限定を付ける（例:「朝会で進捗確認はしない」→「運用・改善の進捗は朝会で追わない」）。発表者の実運用と矛盾しないかを問い返す
6. **アクションは行動レベル** — 締め・次アクションは「いつ・誰が・何を」で書く。時系列（今日／明日から／次の会）に並べると具体性が上がる。準備物には担当者名を明記する
7. **タイトルの流れ** — 見出しだけを順に読んで骨子が伝わるか。動詞で揃えると流れが出る（例: 決める → 大切にする → 見直す）
8. **レイアウトの一貫性** — 同種のページ（カード列挙など）は同じ視覚パターンに揃える。本文は「3秒で見出し、1〜2行で本文」を目安に

## Phase 5: 検証

- **縮小プレビューだけで完了判定しない**。原寸で書き出して目視する（縮小では要素の重なり・微妙なあふれを見落とす）
- チェック項目: 折り返し位置／枠からのあふれ／要素同士の重なり／生成ツールが残した不要なリンク・プレースホルダ
- 最後に全ページを通しで見て、用語の揺れと主張の重複を最終確認する

## フィードバック対応の原則

- **「意味がわからない」と言われたら、文言ではなく構成を疑う**。原因はほぼ次のどれか: 指示対象が見えない（「この1ページ」がどれか分からない等）／他ページとの役割重複／ラベルの曖昧さ
- 修正は必ず横断で影響確認する。同じ表現・同じ概念が他ページにあれば一緒に直す
- **直したら毎ターン、全体のアウトライン（ページ番号＋各ページに載る文章の入れ子）を出してから、何をどう直したかを述べる。**
  差分だけでは前方参照や役割の重複が崩れていないか判断できない
- ユーザーの意図と資料の言い切りがズレていたら、勝手に丸めず「どちらの意味か」を確認する
- 大きな構成変更（ページ入れ替え・削除）の前には、変更理由と付随修正をセットで提示して合意を取る

## 注意事項

- 表に出さないと決めた語・意図は、推敲の過程でも資料に混入させない
- 「読了2分」を超える資料は分割か別紙化を提案する
- 発表時の口頭補足に回す内容（想定問答・注記）はスピーカーノートか別ファイルに逃がし、スライドを薄く保つ
