## 基本ルール（このタスクで順守）
1. **1タスク1ファイル**: 各タスクの開始時に必ず専用の記録用マークダウンファイルを作成する
2. **継続的な更新**: 作業中に気づいたことや決定事項は都度記録
3. **構造化**: 階層的な採番（1-1, 1-2等）で情報を整理し、参照性を高める
4. **一問一答形式**: 一問一答形式を徹底する（複数の質問を同時にしない）
   - 質問が複数あるときは、それらの意図とともに進捗（1/3など）を表示する
5. **段階的詳細化**: 概要から詳細へ、抽象から具体へ進む
6. **PDCAサイクルの徹底**: Plan→Do→Check→Actのサイクルを回して品質を確保
7. **用語の明確化**: ユビキタス言語を定義し、認識を統一する
8. **選択肢の採番**: 複数のパターンや選択肢を提示する際は必ず番号を付ける
   - 例: 「1. Aパターン」「2. Bパターン」「3. Cパターン」
   - ユーザーが「2番で」と簡単に選択できるようにする
9. **タスク独自ルールの追加**: タスク特有の制約や方針を発見したら即座に記録
10. **ファイル・ディレクトリ作成のルール**: 
    - 新しいファイルやディレクトリを作成する場合は、index.mdがあるディレクトリを作業用ルートとして扱う
    - すべての新規作成はindex.mdがある作業用ルート以下に配置する
    - 作業の構造を維持し、適切な階層に配置する
11. **TODOリストの活用**: TodoWriteツールで作業を管理し、中断時は必ず最新の状態を記録
    - **重要**: 最終タスクとして必ず "ユーザーからタスク完了の指示を受ける" を追加する
    - タスクの状態（pending/in_progress/completed）を明確に管理
    - 中断時は現在のTODOリストをマークダウンに記録
    - 再開時は前回の状態から継続
    - **手直し対応**: 手直しが発生した場合は、新たに "ユーザーからタスク完了の指示を受ける" タスクを追加
    - タスク完了の判断は必ずユーザーの明示的な承認を得る

## PDCAサイクル進行ガイド

### Plan（計画）フェーズの進め方
<!-- 成果物が確定するまで対話的に進める -->

#### ステップ1: 目的の明確化（対話）
1. 「今回のタスクで何を達成したいですか？」と質問
2. ユーザーの回答を「目的」セクションに記録
3. 不明点があれば追加質問（1問1答形式）

#### ステップ2: 現状調査と制約確認（対話）
1. 必要に応じてコードベースを調査
2. 「以下の理解で正しいですか？」と確認
   - 現在の状況：〜
   - 制約条件：〜
   - 前提条件：〜

#### ステップ3: 成果物の対話的定義
1. **成果物の提案**
   ```
   以下の成果物を考えていますが、いかがでしょうか？
   
   【必須成果物】
   1. 〜の実装
   2. エラーハンドリング
   3. 基本テスト
   
   【推奨成果物】
   1. 〜の最適化
   
   【オプション】
   1. 〜の追加機能
   
   追加・削除・修正したい項目はありますか？
   ```

2. **ユーザーのフィードバックを反映**
   - 成果物の追加/削除/修正を行う
   - 優先度の調整（必須/推奨/オプション）

3. **完了条件の確認**
   ```
   各成果物の完了条件：
   - 成果物1：〜が動作すること
   - 成果物2：エラーケース〜に対応していること
   
   この完了条件でよろしいですか？
   ```

#### ステップ4: 実装方針の選択（対話）
1. 複数の実装方針を番号付きで提示
   ```
   実装方針を以下から選んでください：
   1. Aパターン：〜
   2. Bパターン：〜
   3. Cパターン：〜
   ```

#### ステップ5: 最終確認とTODO作成
1. 「以下の成果物と方針で進めてよろしいですか？」
2. 承認後、TodoWriteで詳細タスクを作成
   - **必須**: 最終タスクとして「ユーザーからタスク完了の指示を受ける」を追加
3. 「Planフェーズ完了。実行を開始します」と報告

### Do/Check/Act（実行・評価・改善）フェーズの進め方
<!-- 各TODOタスクごとに小さなPDCAサイクルを回す -->

#### 各TODOタスクの実行サイクル
1. **Do（実行）**
   - 1つのTODOタスクを選んでin_progressに変更
   - タスクを実行する
   - 実行内容を記録する

2. **Check（評価）**
   - 実行結果が期待通りか確認
   - エラーや警告がないかチェック
   - 必要に応じて動作確認を実施

3. **Act（改善）**
   - 問題があれば修正
   - タスクをcompletedに変更
   - 手直しが必要な場合：
     - 新たに修正タスクを追加
     - 最後に「ユーザーからタスク完了の指示を受ける」タスクを再度追加
   - 次のタスクへ進むか、ユーザーに確認を求める

#### タスク実行時の報告タイミング
- **即座に報告すべき場合**
  - エラーや予期しない問題が発生した時
  - 設計変更が必要と判断した時
  - ユーザーの判断が必要な選択肢がある時
  
- **定期的に報告する場合**
  - 3-5個のタスクが完了した時点
  - 大きなマイルストーンに到達した時
  - 成果物カテゴリ（必須/推奨/オプション）が完了した時

#### 中断・再開時の処理
- 中断時：現在のTODOリストの状態を必ずマークダウンに記録
- 再開時：in_progressのタスクから継続、なければ次のpendingタスクから開始

## タスク再開時の手順
