# ore-task — タスク台帳の定期更新

Notion 上のタスク台帳を**まとめて棚卸しして最新化する**ときに使う。

単発の操作はこのスキルの対象外。「これタスクにして」「〇〇-12 終わった」は
`docs/task-system/public.md` §5 に従って会話でそのまま処理する。

---

## 前提（起動時に即実行・スキップ禁止）

1. `~/.ai_agent/docs/task-system/public.md` を読む
2. 同ディレクトリの `private.md` を読む（**記述が競合したら private 側を優先**）
3. 対象 DB は private 側 §1 に記載の id で指定する。**`notion-search` で DB を探さない**（旧 DB に誤って書く事故が起きる）
4. private 側が無い、または id が未記入なら**作業を止めて確認する**

> **運用ルールの本体は `docs/task-system/` にある。このスキルは順序・関門・部分実行の制御だけを持つ。**
> ルールを変えたいときは docs 側を直す。このファイルに複製しない（二重管理になった時点で価値が消える）。

---

## 回す順序（4ステップ）

| # | ステップ | 書き込み |
|---|---|---|
| 1 | 棚卸し（確認対象の洗い出し） | なし（読み取りのみ） |
| 2 | 進捗同期 | あり（`y/n` 必須） |
| 3 | Slack 保存済みから起票 | あり（`y/n` 必須） |
| 4 | 順位整理 | あり（`y/n` 必須） |

**なぜこの順序か。**

- 棚卸しを先にやらないと、ステップ2が Slack / GitHub の無限探索になる
- 同期を先にやらないと、既に終わっているタスクを並べ直すことになる
- 起票を順位整理より先にやらないと、新規が末尾に埋もれたまま終わる

---

## ステップ1: 棚卸し（確認対象の洗い出し）

未完了（`Todo` / `Doing` / `Waiting`）を**全件**取得し、各タスクに
**「何を見れば状態が決まるか」** を紐づける。

プロパティだけでなく**本文も読む**。待ち先とリンクは本文にしかない。

### 紐づけの型

| 台帳の状態 | 何を見るか | 何が分かるか |
|---|---|---|
| `Waiting` | 本文の「誰の何待ち」→ 該当する Slack スレッド | 返答が来ていれば `Doing` へ戻す |
| 本文に PR リンク | PR の `state` / マージ時刻 / 自分の review | `MERGED` かつ自分が `APPROVED` なら `Done`。他者が対応していれば `Dropped` |
| 本文に Notion / Figma リンク | そのページの更新・コメント | レビューが済んでいるか |
| `Doing` のまま動きが無い | 直近の自分の作業・発言 | 実態が `Waiting` か、放置か |
| `Due` が超過・接近 | （見に行かない） | ステップ4で先頭へ寄せる |
| 確認手段が無い | **見に行かない** | ステップ2で触らない |

### 提示

| ID | タスク名 | 現 Status | 何を見るか |
|---|---|---|---|

- **ここは読み取りだけなので `y/n` は取らない**（関門は書き込み前だけに置く）
- 表の後に「見なくていいものがあれば言ってください」と添える。ユーザーが削れる形にする
- 併せて「確認手段が無くスキップするもの」の件数を1行で報告する

---

## ステップ2: 進捗同期

**ステップ1で挙げた対象だけを見に行く。台帳全体を漁らない。**

### 調査はサブエージェントに委譲する

確認対象が確定しているので委譲できる。メインのコンテキストを守るため委譲する。

- **委譲の単位は確認手段の種類ごと**（GitHub 系で1つ、Slack 系で1つ）。並列で投げる
- 返させるのは **「タスク / 見たもの / 一次情報 / 状態の判定」だけ**。生ログを返させない
- **書き込みは委譲しない。** メインで承認を取ってから行う

### レビュー表（`public.md` §5 の形式）

| ID | 項目 | Before | After | 根拠 |
|---|---|---|---|---|

- **根拠は一次情報で書く** — PR の `state` / マージ時刻 / Slack の発言と時刻。「〜のはず」は書かない
- **1プロパティ1行。** `Status` と `完了日` と `順位` をまとめない
- **判断が弱いものは弱いと書いて人に委ねる**（review が `COMMENTED` のときの `Waiting` / `Doing` など）

`y/n` を取ってから書き込む。

---

## ステップ3: Slack 保存済みから起票

手順は `public.md` §5「Slack の保存済みから起票」に従う。ここでは制御だけ定める。

- 期間は **`after:` で直近2週間**。間隔が空いていてもそれ以上は遡らない
- **突合用の既存タスクは `Source` が入っているもの全件。** ステップ1で取った未完了だけでは足りない
  （`Done` / `Dropped` でヒットしたら処理済み・見送り済み）
- 検索と仕分けの調査はサブエージェントに委譲してよい。**判定結果だけ返させる**
- 提示は **「起票する」「検討して見送る」の2区分だけ**。対象外は件数のみ
- **同テーマの既存タスクがあれば新規起票せず本文に追記する**（タスク名でも見比べる）

### 順位は末尾 +10 でよい

`public.md` §5 には「運用の一次対応 / 期限が迫る / レビュー依頼なら割り込ませる」とあるが、
**このスキルは直後にステップ4で全体を振り直すため、ここでは末尾 +10 で入れる。**
割り込みの `y/n` を二重に取らない。

`y/n` を取ってから書き込む。

---

## ステップ4: 順位整理

未完了を**種類順**に並べ替え、10刻みで振り直す。

1. 運用からの問い合わせの一次対応
2. 期限が迫っているもの
3. レビュー依頼
4. プロダクトバックログ開発
5. その他

- **全件を順位つきで提示する**（上位N件に絞らない）。**なぜその順かを1行添える**
- 同じ種類の中は `期限` → 放置期間 → 軽さ で並べる
- **`Waiting` は種類の位置を保ったまま、同種内では末尾**
- 期限超過・長く動いていないものを併せて知らせる
- Notion に一括更新 API はないため、**順位が変わったものだけ書く**

`y/n` を取ってから書き込む。

---

## 提示のしかた（全ステップ共通）

### 必ず `Name` を出す

**`ID` 単独で示さない。** 表には必ず `Name` 列を入れる。
ID だけでは何の話か判断できず、読み手が台帳を引き直すことになる。

### 「判断が必要 / 判断不要 / 変更なし」に分ける

全部を1つの表に並べない。**人が読むべき順に3つへ割る。**

| 区分 | 出し方 |
|---|---|
| **判断が必要** | **先頭に置く。** 選択肢を番号で並べ、推奨を1つ示して理由を1行 |
| **判断不要（そのまま書き込む）** | 表で簡潔に。根拠は一次情報 |
| **変更なし** | 表で1行ずつ、または件数だけ |

並列に並べると、判断すべき1件が「変更なし20件」に埋もれる。

### 読み取りに承認を求めない

**調査・取得・突合に `y/n` を取らない。** 関門は**書き込みの直前だけ**に置く。
「このまま調査してよいですか」と聞かない（`instructions/core.md`「読み取り専用の操作は承認不要」）。

---

## 書き込みの規律（全ステップ共通）

- **書き込みの直前に対象を再取得し、提示時との差分を確認する。**
  人が Notion UI で触っていることがあり、セッション中に `Status` が変わる・
  タスクが未完了リストから消える。**差分があれば書き込みを止めて報告する**
- **`Status` を変えたら本文に1行追記する** — `- YYYY-MM-DD <内容>` を `insert_content`（`position: end`）で
- **`Waiting` は誰の何待ちかを必ず書く**
- `Done` / `Dropped` にしたら `完了日` を埋めて `順位` を空にする
- **他者が対応して完了したものは `Done` ではなく `Dropped`**（自分の成果として集計に乗るのを防ぐ）。
  本文に「誰が対応したか」と「自分の関与」を書く
- **書き込みの前に必ず表で `y/n` を取る**

## 部分実行

| 言われ方 | 回すステップ |
|---|---|
| 「棚卸しして」「台帳を更新して」（**デフォルト**） | 1 → 2 → 3 → 4 |
| 「同期だけ」「ステータスを更新して」 | 1 → 2 |
| 「起票だけ」「slack の後でを見て起票して」 | 3（終了時にステップ4を提案する） |
| 「順位整理して」「今の状況は？」 | 4（未完了の取得は必要。確認手段の紐づけは省く） |

**ステップ2の前には必ずステップ1を通す。** 単独で走らせない。

---

## 完了報告

- 起票 N 件 / 更新 N 件 / 順位を振り直した N 件
- **次にやる上位3件**（ID・**`Name`**・なぜ先頭か）
- 期限超過・長く放置されているもの（あれば）
- **提示時から台帳が動いていたもの**（人が UI で触った形跡。あれば）
- 確認手段が無くスキップしたものを1行
